# CZ-Durak-local

**Текущая базовая версия:** `CZ Durak local_47n`

Браузерная сольная версия карточной игры **«Чешский дурак»**: пользователь играет против встроенного бота.  
Проект рассчитан на запуск как обычного HTML-файла на компьютере и может быть опубликован через GitHub Pages.

> Этот README служит одновременно документацией проекта и контекстом для будущих сессий разработки. Перед изменением логики игры сначала сверяться с этим файлом и с актуальным `index.html`.

---

## 1. Назначение проекта

`CZ-Durak-local` — автономный клиент для игры одного человека против компьютера.

Это **не** сетевой вариант Host/Client.  
Вся игровая логика, интерфейс и AI находятся в одном HTML-файле.

Основной сценарий:

```text
Игрок в браузере
        ↓
     index.html
        ↓
  локальная логика
        ↓
 встроенный бот
```

Сервер Railway, WebRTC и signaling для этой версии **не нужны**.

## 2. Основной файл

Главный файл репозитория должен называться:

```text
index.html
```

Исходная версия, из которой создан репозиторий:

```text
CZ-Durak-local_47n
```

Внутри `index.html` находятся:

- HTML-разметка;
- CSS интерфейса;
- JavaScript игровой логики;
- логика бота;
- правила игры;
- подсчёт очков;
- история партий;
- отладочный лог;
- загрузка фонов;
- режим Chance.

Проект не требует npm, сборщика, Node.js или установки библиотек.

```text

```

## 4. Фоны игрового стола

Текущая версия рассчитана максимум на встроенный fallback:

```text
bg1.jpg ... bg44.jpg
```

В коде имеется:

```text
EMBEDDED_BG_FILES = bg1.jpg ... bg44.jpg
```

При веб-запуске программа сначала пытается прочитать:

```text
Pics/backgrounds.json
```

Если манифест отсутствует или не загружается, используется резервный список:

```text
Pics/bg1.jpg
...
Pics/bg44.jpg
```

### backgrounds.json

Для GitHub Pages предпочтительно использовать `Pics/backgrounds.json`.

Пример:

```json
[
  "bg1.jpg",
  "bg2.jpg",
  "bg5.jpg",
  "bg12.jpg"
]
```

Номера файлов **не обязаны идти подряд**.  
Пропуски допустимы, если список в `backgrounds.json` содержит только реально существующие файлы.

Кнопка:

```text
BG
```

переключает фон по кругу.

Клавиша:

```text
ArrowLeft
```

переключает фон назад.

## 5. Фон кнопок

Игра автоматически ищет фон кнопок в:

```text
Pics/Buttons/
```

Поддерживаются расширения:

```text
.jpg
.jpeg
.png
.webp
```

Код ищет, в частности:

```text
button_bg.*
bg.*
buttons.*
button_bg1..40.*
btn1..40.*
button1..40.*
bg1..40.*
```

Поэтому желательно хранить один основной файл с понятным именем, например:

```text
Pics/Buttons/button_bg.jpg
```

## 6. Варианты правил игры

В интерфейсе доступны два режима:

```text
101
Bridge
```

### Режим 101

Специальные карты:

- 6 — соперник берёт 1 карту и пропускает ход;
- 7 — соперник берёт 2 карты и пропускает ход;
- Король червей — соперник берёт 4 карты и пропускает ход;
- Туз — соперник пропускает ход;
- Дама — позволяет заказать масть.

### Режим Bridge

Специальные карты:

- 6 — соперник берёт 4 карты и пропускает ход;
- 7 — соперник берёт 2 карты и **не** пропускает ход;
- Туз — соперник пропускает ход;
- Дама — позволяет заказать масть.

Даму любой масти можно положить на любую карту.

## 7. Подсчёт очков

Стоимость карт:

```text
J = 2
Q = 3
K = 4
A = 11
остальные = номинал карты
```

Особые правила:

- одна оставшаяся Дама — 20 очков;
- одна оставшаяся Дама пик — 40 очков;
- завершение раунда Дамой — минус 20 очков победителю;
- завершение Дамой пик — минус 40 очков;
- ровно 101 очко сбрасывается в 0;
- игрок, превысивший 101 очко, проигрывает матч.

### Правило четырёх дам

Если у игрока на руках оказываются ровно четыре Дамы:

- сет завершается;
- сопернику начисляется `+102`.

---

## 8. Настройки партии

В верхней панели доступны настройки:

### Запрет добора

```text
2 карты
1 карта
```

Определяет, при каком количестве доступных ходов кнопка добора из колоды блокируется.

### Кто ходит первым в новом сете

Варианты:

```text
Соперник
Игрок
Случайно
Победитель прошлого сета
Проигравший прошлого сета
```

### Поведение пустой колоды

```text
Перемешать сброс
Просто перевернуть сброс
```

Последняя карта на столе остаётся, остальные карты сброса возвращаются в колоду.

---

## 9. Уровни бота

Доступны:

```text
Easy
Normal
Smart
Pro
```

### Easy

Почти случайный выбор допустимого хода.

### Normal

Использует базовую оценку:

- специальные карты;
- номинал;
- связи по масти и достоинству.

### Smart

Дополнительно учитывает:

- возможные цепочки ходов;
- гибкость оставшейся руки;
- возможность закончить комбинацией;
- состояние руки игрока.

### Pro

Использует более агрессивную оценку:

- моделирование слабых мастей и достоинств игрока;
- оценку вероятности ответа;
- давление при малом количестве карт у игрока;
- сохранение стратегически важных карт;
- выбор более длинных цепочек;
- защиту от невыгодного завершения руки.

## 10. Chance

Кнопка:

```text
Chance
```

переключает режимы:

```text
Chance
Chance V
Chance H
```

Функция оценивает вероятности появления подходящих карт.

Она использует:

- известные карты;
- карты игрока;
- видимые карты сброса;
- неизвестные карты;
- заказанную масть;
- режим восстановления колоды.

В режиме `flip`, если порядок возврата сброса известен, Chance может показать следующую карту с вероятностью 100%.

---

## 11. История партии

Кнопка:

```text
History
```

показывает:

- завершённые сеты;
- счёт после каждого сета;
- завершённые игры;
- незавершённые игры;
- общий счёт;
- статистику по победам.

История существует в памяти текущей браузерной сессии.

## 12. Логи и DEBUG

Кнопки:

```text
LOG OFF / LOG ON
DEBUG OFF / DEBUG ON
Folder
```

### Folder

При поддержке браузером File System Access API пользователь может выбрать папку на диске.

Программа создаёт внутри выбранной папки подпапку:

```text
1
```

и сохраняет туда:

```text
CZ_Durak_<timestamp>_game.txt
CZ_Durak_<timestamp>_debug.txt
```

### Важно

Прямая запись на диск зависит от поддержки браузером:

```javascript
window.showDirectoryPicker()
```

Если API недоступен, игру это не ломает — историю можно смотреть через кнопку `History`.

## 13. Перетаскивание карт

Карты игрока можно менять местами drag-and-drop.

Это влияет только на удобство расположения руки и не изменяет правила игры.

## 14. NEW GAME и NEXT SET

```text
NEXT SET
```

начинает следующий сет, сохраняя общий счёт.

```text
NEW GAME
```

начинает новую игру и сбрасывает общий счёт.

Если матч уже завершён, `NEXT SET` блокируется.

## 15. Локальный запуск

Для обычной игры достаточно открыть:

```text
index.html
```

в браузере.

Предпочтительный браузер на Windows:

```text
Google Chrome
```

Основная логика игры не требует веб-сервера.

### Особенность backgrounds.json

При запуске через:

```text
file://
```

код специально не загружает `backgrounds.json` через `fetch`.

В этом случае используется резервный список:

```text
bg1.jpg ... bg44.jpg
```

Поэтому локально фоновые JPG должны находиться в правильной папке `Pics`.

## 17. Что НЕ относится к этому проекту

Этот репозиторий — **соло-версия**.

В нём не нужны:

- Railway;
- WebSocket signaling;
- WebRTC;
- Host;
- Client;
- offer/answer;
- комнаты сетевой игры.

Не переносить сетевую архитектуру из `CZ-Durak_client` / Host-версии без отдельного решения.

## 18. Правило будущих изменений

При дальнейшей разработке:

1. Сначала сохранить рабочую версию.
2. Новую версию нумеровать последовательно:
   ```text
   local_48
   local_49
   ...
   ```
3. Не менять одновременно игровую логику и внешний вид без необходимости.
4. Не ломать относительные пути `Pics/...`.
5. Перед изменением AI проверить уровни `Easy / Normal / Smart / Pro`.
6. После изменений проверить оба режима:
   ```text
   101
   Bridge
   ```
7. Проверить:
   - начало нового сета;
   - завершение сета;
   - 101 → 0;
   - четыре дамы;
   - окончание Дамой и Дамой пик;
   - восстановление колоды;
   - заказ масти;
   - History;
   - Chance;
   - BG;
   - LOG и DEBUG.
